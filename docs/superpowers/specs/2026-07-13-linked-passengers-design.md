# 连体乘客机制设计

## 目标

为左右乘客队列加入由连续同色乘客排组成的连体链。连体链可以包含 2 排、3 排、4 排或更多排，但必须作为不可拆分单位整体进入传送带，并在同一辆车容量足够时同步上车。

该机制强化车辆剩余容量规划，不改变乘客真实颜色、关卡队列顺序、车辆座位单位、车辆离场条件或基础胜负语义。

## 非目标

- 不在同一局同时叠加问号乘客、星星乘客或其他乘客机制。
- 不允许不同颜色组成同一条连体链。
- 不允许连体链部分上车、空间不足时自动拆链或中途改变链长。
- 不把整条链压缩成一个逻辑乘客或一个传送带槽位。
- 不持久化机制设置到 `localStorage` 或 URL。

## 术语

- **排**：当前游戏中的一个四人乘客组，也是车辆容量和 `boardedGroups` 的一个单位。
- **连体链**：同一侧队列中连续、同色的 2–N 排乘客。
- **链首**：队列和传送带移动方向上的最前排，是入带和上车判断的唯一触发成员。
- **批次**：基础模型用于统一处理普通单排和连体链的通用单位。普通排是长度 1 的批次，连体链是长度 N 的批次。

## 核心玩法规则

### 链长与颜色

- 连体链最短为 2 排。
- 链长上限取当前关卡所有车辆的最大座位容量；当前 level18 上限为 10 排。
- 一条链的全部成员必须来自同一侧队列的一段连续同色序列。
- 一排最多属于一条链；不同链不得重叠。
- 同一个长同色连续段可以包含多条独立连体链，链之间允许存在普通乘客。

### 等待队列

- 连体链是不可拆分批次。
- 初始可见等待队列只装入完整批次。如果剩余可见容量不足以容纳下一条链，则保留空位，整条链留在后续队列中。
- 后续补队同样只补入完整批次。必须先空出足够位置，才把整条链一次加入可见等待队列。
- 上述规则不得改变任何乘客的真实颜色或绝对队列序号。

### 进入环形传送带

- 链首到达队列入口时，当前越过入口的槽作为链首槽；游戏再沿传送带移动方向的反方向收集紧随其后的 N-1 个槽，使链首始终位于整条链的最前方。
- N 个槽全部为空时，整条链同时进入，并按链内顺序占据这些连续槽位。
- 任一槽已占用时，整条链继续等待，不允许部分进入。
- 连续槽位允许跨越环形数组的末尾和开头。
- 左右入口按现有更新顺序尝试入带；先成功的批次立即占用槽位，后续入口不得复用已占槽位。
- 链进入后，各成员以相同传送带速度移动，始终保持连续顺序。

### 原子上车

- 只有链首经过上车口时才触发连体上车判断；链内其他成员经过上车口不单独判断。
- 可上车车辆必须同时满足：已经到站、颜色相同、剩余座位不少于整条链长度。
- 满足条件时，N 排在同一逻辑更新中全部上车：同时清除 N 个槽位、车辆 `boardedGroups` 增加 N，并产生一个聚合批量上车事件。
- 不满足条件时零排上车，整条链继续循环。
- 普通单排继续使用原有上车规则。
- `remainingGroups` 和按颜色统计继续按真实排数计算，不把一条链计为一排。
- 车辆满载、离场、获胜和失败仍由基础规则决定；可上车性判断必须把连体链视为原子批次，不能把链内成员误判为可单独上车。

## 两种独立生成方式

### 概率随机模式

- 默认模式为 `chance`。
- 默认连体起点概率为 `0.3`，试验台允许设置 `0..1`。
- 最小链长固定为 2。
- 默认最大链长为当前关卡最大车辆容量，level18 为 10；试验台允许设置 `2..关卡最大车辆容量`。
- 每次重置为两条完整队列重新生成整局链计划；真实颜色序列保持不变。

扫描算法按每条队列从绝对序号 0 开始：

1. 计算当前位置向后的剩余连续同色长度。
2. 若长度小于 2，则当前位置为普通排并前进一位。
3. 若长度至少为 2，则对当前位置执行一次起点概率判断。
4. 未命中时当前位置为普通排并前进一位；下一个位置仍可成为链首。
5. 命中时，计算 `allowedMax = min(剩余连续同色长度, 设置的最大链长, 关卡最大车辆容量)`。
6. 在闭区间 `2..allowedMax` 中等概率抽取整数链长，分配唯一链 ID，并一次跳过整条链。
7. 链结束后继续扫描剩余队列，因此一个长同色段可产生多条链。

随机数由游戏注入，便于覆盖边界和重置行为。概率判断与链长抽取是两次独立随机调用；`authored` 模式不得调用随机函数。

### 关卡标记模式

- 模式 ID 为 `authored`。
- 数据路径为 `level.mechanics['linked-passengers'].authoredChains`。
- `authoredChains` 包含两条与完整乘客队列对齐的整数数组。
- 数组值 `N >= 2` 表示该绝对位置是一条长度 N 的连体链起点；其他位置写 `0`。
- 链内后续成员位置保持 `0`，不重复写链长。
- 首份 level18 演示数据在左右队列中均衡放置 2、3、4、6、8、10 排链，并避免连续堆叠，便于观察不同长度的玩法差异。
- 每次重置读取同一份固定数据，位置与链长完全一致。

## 关卡数据校验与容错

- 只有有限整数且 `N >= 2` 才是候选链长。
- 链长不得超过当前关卡最大车辆容量。
- 链不得越过当前队列末尾。
- 候选范围内所有乘客必须同色。
- 候选不得与此前已接受的链重叠；按绝对序号从小到大处理，先出现的有效链优先。
- 任一条件失败时只忽略当前起点，不得自动截短或改写链长；扫描继续前进一位，后续未被有效链占用的位置仍可声明其他候选链。
- 缺少配置、缺行、缺项、非数组行和多余项均安全忽略。
- 无有效标记时机制仍能运行，并显示 0 条固定连体链。
- 异常配置最多发出一次简短警告，不阻止启动、重置或机制切换。

## 选择的技术路线

采用“机制模块拥有链状态，基础模型提供通用乘客批次钩子”的路线。

### 采用原因

- 真实乘客仍逐排占据队列、传送带槽位和车辆容量，保持基础语义。
- 连体生成与原子判断集中在独立机制模块中，不在 `main.js` 或基础模型中扩张机制 ID 分支。
- 基础模型新增的是长度 1..N 都适用的通用批次能力，可供未来组合乘客机制复用。
- 问号乘客和星星乘客仍走原有单排路径，不需要了解连体规则。

### 不采用的路线

- **超级乘客实体**：整链占一个逻辑槽位会改变传送带容量和间距，与已确认的连续 N 槽规则冲突。
- **基础模块专用分支**：在 `game-model.js`、`scene-view.js` 和 `main.js` 直接判断机制 ID，会破坏现有隔离边界。

## 模块边界

### `src/mechanics/linked-passengers/`

- `index.js`
  - 拥有定义、状态和模块导出。
  - 在全部完成门槛通过前保持 `planned`。
- `model.js`
  - 规范化模式、概率和最大链长。
  - 生成完整概率链计划或解析关卡标记。
  - 为队列项提供链 ID、链内序号、链长、链首和链尾元数据。
  - 提供通用批次长度、入带批次和原子上车候选钩子。
  - 深拷贝快照数据并装饰全局机制状态。
- `view.js`、`styles.css`
  - 提供模式、概率、最大链长和关卡统计控件。
  - 只提交规范化设置，不直接重置游戏或操作场景。

### `src/game-model.js`

- 保留真实乘客排作为最小存储和计数单位。
- 为完整队列使用一致的绝对序号，并允许 runtime 预先生成整局批次计划。
- 初始建队和后续补队通过通用批次长度判断，避免在可见边界拆链。
- 队列入口支持一次移除 1..N 个连续队列项并占用 1..N 个连续环形槽位。
- 上车口支持 runtime 返回 1..N 个原子槽位候选，并统一验证车辆后一次提交。
- 聚合事件包含 `groupCount`、`passengerIds`、`slotIndices`、`chainId` 和 `vehicleId`，普通乘客事件保持兼容。
- 失败检测和 `hasBoardablePassenger()` 使用原子批次候选，不把链内成员单独计算。
- 不判断连体概率、关卡整数数组或视觉连杆。

### `src/mechanic-library.js` 与 `src/main.js`

- 复用现有通用详情扩展入口和页面会话机制设置。
- 默认设置为 `{ mode: 'chance', chance: 0.3, maxLength: 10 }`，其中 `maxLength` 在运行时按关卡容量再次限制。
- 当前机制设置提交后重建 runtime、重置游戏并重新初始化队列一次。
- 切换到其他机制后设置仍留在当前页面内；刷新恢复默认值。
- 不新增 `localStorage` 键或 URL 参数。

### `src/scene-view.js`

- 根据快照链元数据创建、复用并清理连体视觉。
- 等待队列和传送带分别按当前成员世界位置绘制分段顶部连杆。
- 连杆跟随相邻排位置，允许传送带链跨越环形数组首尾。
- 链首显示链条图标与 `×N` 长度徽章。
- 批量上车事件通过成员槽位和乘客 ID 捕获当前显示对象的变换，创建一次性瞬态视觉，不把动画状态写回游戏模型。
- `resetVersion`、机制切换、视图复用和销毁必须清除旧连杆、徽章和瞬态动画。

## 数据结构

每个连体成员的快照元数据使用独立对象：

```js
{
  linkedPassenger: {
    chainId: 7,
    memberIndex: 0,
    length: 4,
    isHead: true,
    isTail: false
  }
}
```

普通乘客使用 `linkedPassenger: null`。链 ID 只需在一次 reset generation 内唯一；重置后可以从初始值重新生成，因为场景同时使用 `resetVersion` 去重。

全局机制状态至少包含：

```js
{
  linkedPassengers: {
    mode: 'chance',
    chance: 0.3,
    maxLength: 10,
    chainCount: 0,
    linkedGroupCount: 0,
    longestChain: 0
  }
}
```

统计覆盖两条完整队列，而不只覆盖当前可见部分。

## 数据流

### 重置和生成链计划

1. 游戏使用当前页面会话设置创建 `linked-passengers` runtime。
2. runtime 读取完整左右颜色队列和最大车辆容量。
3. runtime 按 `chance` 或 `authored` 规则生成不可变链计划与统计。
4. 游戏创建可见等待队列时查询批次长度，只装入完整批次。
5. 未进入可见区的真实颜色保持在后续队列，并保留绝对序号语义。

### 后续补队

1. 一个普通排或整条链离开等待队列后，游戏计算当前空余容量。
2. 查看后续队列头部批次长度。
3. 空余容量不足时不补入任何成员。
4. 容量足够时一次创建并追加整批成员，然后继续尝试下一个完整批次。

### 整链入带

1. 链首到达入口，runtime 返回链长和当前等待队列中的成员集合。
2. 游戏把当前越过入口的槽作为链首槽，并沿移动反方向收集紧随其后的 N-1 个环形槽位。
3. 全部为空时，一次从等待队列移除 N 排并填入 N 个槽；否则保持原状。
4. runtime 把链元数据克隆到各槽位，链首仍是唯一入带/上车触发成员。

### 整链上车

1. 链首跨过上车点，runtime 返回该链的完整槽位候选。
2. 游戏查找同色、已到站且剩余容量至少为 N 的车辆。
3. 未找到时不改变任何成员。
4. 找到时一次增加 N 排已上车数、清理 N 个槽、触发一次聚合事件并检查车辆满载/胜负。
5. 场景消费聚合事件，播放同步反馈；逻辑结果不等待动画完成。

## 试验台控件

- “生成方式”：`概率随机` / `关卡标记`。
- 概率模式显示：
  - “连体起点概率”范围 `0%–100%`，默认 30%。
  - “最大链长”范围 `2..关卡最大车辆容量`，level18 默认 10。
- 控件拖动时只更新读数；`change`、失焦或键盘确认时规范化并提交一次。
- 关卡模式隐藏概率控件，显示：
  - 固定链条数；
  - 固定连体排数；
  - 最长链长度。
- 设置仅存在于当前页面会话，不写入存储或 URL。

## 视觉与动效

### 顶部连杆

- 使用用户选择的顶部连杆方案。
- 每对相邻成员之间绘制一段青绿色连杆，端点跟随两排乘客的当前世界位置。
- 连杆位于人物头部上方，避免覆盖身体颜色和四人队形。
- 链首挂接链条图标和 `×N` 徽章；徽章始终朝向相机并在移动端保持可读。
- 等待队列、传送带和环形首尾均使用同一套链元数据，不通过屏幕距离猜测成员关系。

### 同步上车反馈

- 链首成功触发上车时，顶部连杆先闪亮。
- N 排沿短扇形弧线在约 250ms 内同步飞向目标车辆。
- 车辆附近显示一次 `×N`，并播放一次聚合烟雾和一次上车音效。
- 动画不锁输入，游戏逻辑在事件产生时立即完成。
- 同一聚合事件只播放一次；场景通过事件 ID 和 reset generation 去重。

### 减少动态效果

- `prefers-reduced-motion: reduce` 下不使用扇形位移、缩放或弹跳。
- 保留连杆亮度变化、成员同步淡出、车辆亮度反馈和 `×N` 计数。
- 动效分支读取实时媒体查询，设置变化后无需刷新即可生效。
