# 问号乘客机制设计

## 目标

为左右等待队列加入部分颜色未知的乘客组，让玩家在车辆与停车位调度时保留应对未知颜色的余量。机制只改变等待阶段的信息可见性，不改变真实乘客顺序、颜色匹配、上车、车辆离场或胜负规则。

本机制支持两种互斥的生成方式：

1. `chance`：每组乘客独立按固定概率成为问号组。
2. `authored`：完全依据关卡数据中的布尔标记决定问号组，不执行随机补充。

试验台默认使用 `chance`，默认概率为 30%。

## 玩家体验

- 每个队列项代表一组 4 名同色乘客，问号状态整组生效。
- 问号只存在于左右等待队列。进入环形传送带后，乘客立即显示真实颜色。
- 等待中的问号组保留原乘客模型、动作和阴影，但使用统一的中性灰材质。
- 组内每名乘客显示高对比问号徽章，确保桌面和窄屏都能辨认。
- 揭示发生在进入传送带的当帧，同时播放约 250ms 的短闪、轻微弹出和问号淡出。
- `prefers-reduced-motion: reduce` 下取消位移与缩放，只保留颜色切换和短暂亮度变化。
- 揭示反馈不拦截指针输入，不暂停游戏，也不改变布局。

## 生成模式

### 概率随机模式

- 每个新建队列项独立调用一次注入的随机函数。
- 当随机值小于配置概率时，该队列项成为问号组。
- 默认概率为 `0.3`，试验台允许设置 `0..1`。
- 每次重置重新创建队列项并重新抽取问号位置。
- 重置只改变问号分布；真实颜色队列保持关卡原始顺序。
- 不增加“至少一个问号”或均匀分布保证，保持固定概率语义。

### 关卡标记模式

- 关卡数据在 `level.mechanics['question-passenger'].authoredMasks` 中为左右两条 `passengerQueues` 各提供一个等长布尔数组。
- 数组中的 `true` 表示同位置队列项是问号组；其他值均视为非问号组。
- 运行时不调用随机函数，也不根据概率补充标记。
- 首份 level12 演示标记使用固定、约 30% 的分布；该数据写入关卡定义，每次重置完全一致。
- 两条标记数组必须覆盖初始可见队列和后续补入队列，而不只覆盖 `queueCapacity` 范围。

## 选择的技术路线

采用独立机制模块，并通过通用 runtime、详情扩展和场景快照契约接入基础运行时。

未采用以下路线：

- 在 `game-model.js`、`scene-view.js` 和机制库中按机制 ID 增加专用分支。这会形成持续增长的分支树。
- 只在场景层随机遮色。这会使游戏模型不知道问号分配，难以可靠支持关卡标记、重置和自动化测试。

## 模块边界

### 问号乘客模块

- `src/mechanics/question-passenger/index.js`
  - 拥有机制元数据。
  - 导出问号乘客 runtime factory。
  - 在实现和验证完成前保持 `planned`；通过全部验收门槛后改为 `playable`。
- `src/mechanics/question-passenger/model.js`
  - 规范化 `chance`、`authored` 和概率配置。
  - 根据随机函数或关卡布尔数组创建队列项问号状态。
  - 在乘客进入传送带时解除隐藏并产生一次性揭示版本。
  - 克隆队列项、槽位和全局机制快照。
- `src/mechanics/question-passenger/view.js`
  - 创建机制详情区设置控件。
  - 同步当前模式、概率读数和关卡标记统计。
  - 将已确认的设置提交给通用重配入口。
- `src/mechanics/question-passenger/styles.css`
  - 拥有机制详情设置块的布局、状态和窄屏样式。

### 通用运行时

- `src/game-model.js`
  - 创建 runtime 时提供 `{ random, level, options }`；页面会话选项使用 `{ mode, chance }`，关卡固定标记只从 `level` 读取。
  - 创建机制队列项数据时提供 `queueIndex` 和队列内绝对序号。
  - 为初始队列和后续补入队列维护同一套绝对序号语义。
  - 提供更新指定机制选项、重建当前 runtime 并重置游戏的通用能力。
  - 不判断问号概率、布尔标记或视觉表现。
- `src/mechanic-library.js`
  - 提供通用详情扩展挂载入口。
  - 在详情重绘、机制切换和销毁时正确挂载或清理扩展内容。
  - 不包含 `question-passenger` 专用分支。
- `src/main.js`
  - 保存当前页面会话内的机制设置。
  - 连接详情扩展、游戏重配、场景队列重新初始化和 UI 同步。
  - 切换离开再返回时保留本次页面会话的设置；刷新后恢复默认值。
- `src/scene-view.js`
  - 只消费快照中的问号状态。
  - 为等待队列应用中性灰材质和问号徽章。
  - 根据乘客 ID 与揭示版本播放一次揭示反馈。
  - 不判断生成模式、概率或关卡标记。

## 状态设计

单个等待队列项和传送带槽位携带：

```js
{
  questionPassenger: {
    hidden: true,
    wasHidden: true,
    revealVersion: 0
  }
}
```

- `hidden`：当前是否应隐藏真实颜色。等待队列中的问号组为 `true`；进入传送带后为 `false`。
- `wasHidden`：该组是否以问号状态进入传送带，用于区分普通组和刚揭示的组。
- `revealVersion`：进入传送带时从 0 递增一次。场景按乘客 ID 与版本去重，逐帧同步不得重复播放揭示。

全局机制状态暴露当前生效配置与关卡统计：

```js
{
  questionPassenger: {
    mode: 'chance',
    chance: 0.3,
    authoredMarked: 0,
    authoredTotal: 0
  }
}
```

真实 `colorIndex` 始终保留在基础队列项和槽位中。问号状态只是独立的可见性元数据。

## 数据流

### 重置和创建队列项

1. 游戏根据当前机制设置创建 question-passenger runtime。
2. 游戏重建左右队列，并向 runtime 提供 `queueIndex` 和绝对序号。
3. `chance` 模式对每项执行一次随机判断；`authored` 模式读取对应布尔值。
4. 队列项快照保留真实颜色，并附加问号状态。
5. SceneView 对 `hidden: true` 的等待队列组应用中性灰材质和问号徽章。

### 进入环形传送带

1. 基础游戏把乘客 ID、真实颜色和机制数据移入空槽位。
2. runtime 将 `hidden` 设为 `false`，保留 `wasHidden`，并递增 `revealVersion`。
3. 槽位快照在进入传送带的第一帧已经包含真实颜色。
4. SceneView 检测新的乘客 ID 与揭示版本，播放一次短揭示反馈。
5. 后续逐帧同步不再重复触发。

### 修改试验台设置

1. 用户切换模式，或在概率控件上完成一次调整。
2. 详情控件提交规范化设置。
3. 主线程更新本次页面会话内的机制选项。
4. 当前 runtime 被重建，游戏和机制 UI 重置，场景重新初始化队列。
5. 新设置立即用于完整的新一局。

## 试验台控件

机制详情区增加紧凑设置块：

- “生成方式”：`概率随机` / `关卡标记`。
- 概率模式显示 `0%–100%` 控件和当前读数，默认 30%。
- 拖动时只更新读数；松开、失焦或键盘确认时提交一次并重置，避免连续重建游戏。
- 关卡标记模式隐藏概率控件，显示固定标记统计，例如“左右队列共 132/438 组为问号”。
- 切换模式后立即重置当前机制。
- 设置仅保留在当前页面会话，不写入 `localStorage`，也不新增 URL 参数。

## 容错

- 非法模式回退到 `chance`。
- 非有限概率回退到 `0.3`；有限概率限制到 `0..1`。
- 关卡标记只有严格的 `true` 才生效。
- 标记数组缺失、缺行或长度不足时，缺失位置按 `false` 处理。
- 标记数组多余项忽略。
- 无有效关卡标记时，`authored` 模式仍可运行并显示 0 个问号。
- 配置异常最多发出简短警告，不阻止启动、机制切换或重置。
- 重置、切换和销毁必须清除揭示中的临时视觉状态。

- `chance` 默认 30%，重置后问号位置重新分配。
- `authored` 使用固定演示分布，多次重置保持一致。
- 问号只出现在左右等待队列，模型、动作和阴影正常。
- 问号徽章在桌面和手机上可读，不遮挡队列理解。
- 乘客进入传送带的当帧显示真实颜色，揭示动画只播放一次。
- reduced-motion 下没有明显位移或缩放，但揭示结果仍清晰。
- 模式、概率、重置、机制切换和移动端抽屉工作正常。
- 页面、控制台和资源请求无错误。
