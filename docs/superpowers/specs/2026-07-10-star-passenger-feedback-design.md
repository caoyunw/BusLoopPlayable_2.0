# 星星乘客反馈优化设计

## 目标

让玩家无需阅读说明就能理解两件事：

1. 星星乘客的奖励最多持续 3 次出口经过，每经过一次出口剩余次数减 1。
2. 收集星星会推进一个可重复充满的金币进度，目标为 20 枚；充满时获得强烈但不中断操作的庆祝反馈。

本次只增强星星乘客的可读性和奖励反馈，不改变乘客生成概率、上车条件、胜负条件，也不增加实际道具奖励或领取流程。

## 已确认方案

### 剩余次数标识

采用数字徽章方案。

- 每个仍持有奖励的星星乘客，星星右上角显示剩余次数 `3`、`2` 或 `1`。
- 等待队列中的星星乘客初始显示 `3`。
- 乘客进入传送带后继续显示相同标识。
- 每次经过出口计数点时，乘客旁弹出一次 `-1`，数字同步减少。
- 剩余次数归零时，星星和数字徽章一起消失；乘客继续留在传送带上。
- 数字徽章使用高对比色、白色描边和稳定尺寸，避免被乘客颜色或场景背景吞没。
- `-1` 反馈只在真正发生出口计数时播放，不因普通帧同步重复触发。

### 金币充能

金币充能使用循环进度，目标固定为 20。

- 初始显示 `0/20`。
- 每名有效星星乘客成功上车，当前充能增加 1。
- 普通收集沿用星星飞向进度栏的反馈，同时更新计数和进度条。
- 第 20 枚金币到达时，进度先显示 `20/20`，并触发一次完整充能事件。
- 庆祝动效结束后，当前进度显示为 `0/20`，下一枚金币从 `1/20` 继续。
- 模型记录累计收集数和累计充满轮数，保证充满事件可以重复触发。
- 充满不暂停游戏、不弹出确认框，也不发放额外道具。

## 充满动效

庆祝动效采用“进度条爆闪 + 金币喷发 + 星芒冲击”三层反馈：

1. 进度条在 `20/20` 时变亮并产生一次金色扫光。
2. HUD 周围生成金币和星芒粒子，向外喷发后淡出。
3. HUD 产生一次短促缩放和光圈扩散，强化充满时刻。

整体时长约 1 秒。动效层使用 `pointer-events: none`，不遮挡车辆点击；同一充满轮次只触发一次。动效结束后，HUD 从 `20/20` 切换到 `0/20`，避免第 20 枚金币直接被视觉上吞掉。

需要尊重 `prefers-reduced-motion`：减少粒子位移和缩放幅度，但仍保留颜色、计数和亮度变化，使信息不依赖动画才能理解。

## 状态设计

全局 `starReward` 状态扩展为：

```js
{
  enabled: true,
  coins: 0,
  charge: 0,
  collected: 0,
  expired: 0,
  target: 20,
  completedCharges: 0
}
```

- `coins`：累计收集的星星金币总数，持续增长。
- `charge`：当前充能轮次中的进度，范围为 `0..19`。
- `target`：固定目标 20，仍允许测试通过配置覆盖。
- `completedCharges`：累计充满轮数，用于可靠触发 UI 庆祝。

单个乘客的 `starReward` 状态扩展为：

```js
{
  active: true,
  exitPasses: 0,
  remainingPasses: 3,
  expired: false,
  decrementVersion: 0
}
```

- `remainingPasses`：场景数字徽章直接读取的剩余次数。
- `decrementVersion`：每次经过出口递增，用于让场景表现只播放一次 `-1`。
- 奖励过期后 `active` 设为 `false`、`remainingPasses` 设为 `0`、`expired` 设为 `true`。

## 数据流

### 经过出口

1. `BusLoopGame` 检测乘客经过出口。
2. 星星乘客 runtime 的 `onPassengerExitPassed` 增加 `exitPasses` 和 `decrementVersion`。
3. runtime 重新计算 `remainingPasses`。
4. 场景同步数字徽章，并根据 `decrementVersion` 的变化播放一次 `-1`。
5. 剩余次数归零时隐藏星星标识，乘客本体不受影响。

### 成功上车

1. `onPassengerBoarded` 确认奖励仍有效。
2. `coins`、`collected` 和 `charge` 增加 1。
3. 当 `charge` 达到 `target` 时，`completedCharges` 增加 1，并把模型中的 `charge` 归零。
4. HUD 发现 `completedCharges` 变化，先以视觉暂存状态显示 `20/20` 并播放庆祝。
5. 动效结束后 HUD 读取模型的 `charge: 0`，显示 `0/20`。

## 模块边界

- `src/mechanics/star-passenger/model.js`：拥有剩余次数、当前充能、累计充满轮次和事件状态。
- `src/mechanics/star-passenger/view.js`：拥有 HUD 数字、普通收集飞行、充满庆祝和视觉暂存。
- `src/mechanics/star-passenger/styles.css`：拥有 HUD、庆祝粒子、扫光、光圈和 reduced-motion 样式。
- `src/scene-view.js`：只负责读取通用星星奖励快照并表现乘客头顶标识；不拥有充能规则。
- `test/star-passenger-mechanic.test.js`：覆盖状态递减、过期、循环充能和 UI/场景接线。

不新增全局 HTML 节点；星星乘客 UI 继续由机制 controller 动态创建。

## 边界情况

- 非星星乘客不显示徽章，也不产生 `-1`。
- 奖励已经过期时，重复经过出口不继续递减，不重复增加过期计数。
- 奖励在剩余 1 次时成功上车，仍正常获得金币。
- 第 20 枚金币同时只触发一次充满事件；后续第 21 枚计为新一轮 `1/20`。
- 机制 reset 时清除视觉暂存、定时器、粒子和上一次充满轮次。
- 切换离开星星乘客时立即隐藏 HUD 并移除庆祝层，避免残留。
- 连续快速触发时，普通飞行效果可以并存；充满庆祝按 `completedCharges` 去重。

## 测试与验收

自动化测试需要覆盖：

- 新星星乘客初始 `remainingPasses` 为 3。
- 每次经过出口后依次变为 2、1、0，并递增 `decrementVersion`。
- 归零时奖励过期但乘客仍保留。
- 第 19 枚后显示当前充能 19；第 20 枚后 `charge` 归零、`completedCharges` 增加 1。
- 第 21 枚进入新一轮，`charge` 为 1。
- HUD 默认目标为 20，并包含普通收集和充满庆祝入口。
- 场景星星徽章读取 `remainingPasses`，并根据 `decrementVersion` 触发 `-1`。

手动视觉验收需要覆盖：

- 桌面和手机尺寸下，`3/2/1` 都能清楚辨认且不遮挡乘客主体。
- 乘客经过出口时只弹出一次 `-1`。
- 20/20 庆祝足够醒目，但不遮挡车辆操作，不导致布局位移。
- 庆祝结束后显示 0/20，下一枚星星显示 1/20。
- 开启 reduced motion 后仍能理解递减和充满结果。
